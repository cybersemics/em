# Accessibility

How the Liminal UI stays usable for people who need larger text. Liminal UI is em's design language: white on black, over a soft background glow, with translucent glass panels such as the [Dialog](../../src/recipes/dialogRecipe.ts) and the [Command Center](../../src/components/CommandCenter/CommandCenter.tsx).

## Font size

The user sets a font size from 8 to 40px, 16 by default, with the Increase Font Size and Decrease Font Size commands or the font buttons in the footer. It is stored in `state.fontSize` ([`constants.ts`](../../src/constants.ts) holds `MIN_FONT_SIZE`, `DEFAULT_FONT_SIZE` and `MAX_FONT_SIZE`).

[`AppComponent`](../../src/components/AppComponent.tsx) writes it to the font size of `<html>`, so **1rem is always the user's font size**. Anything sized in `rem` follows the setting with no code of its own.

`<body>` keeps a fixed font size of 16px ([`panda.config.ts`](../../panda.config.ts)). Text that inherits its size from the page rather than from `<html>` therefore stays at 16px, and so does every `em` unit inside it. An overlay rendered into `<body>`, such as the sidebar, has to set `fontSize: '1rem'` on its root for its `em`-sized text to follow the user. [`SidebarContent`](../../src/components/Sidebar/SidebarContent.tsx) does this.

## Sizing rules

Every size answers one question: should it grow when the user asks for larger text? Text must grow, because that is what the user asked for. Space between things should grow only where growing does not take room away from the text.

| Value | Unit | Why |
|---|---|---|
| Text, and its line height | `rem` | It is what the user asked to enlarge. |
| Vertical spacing: padding, margins and gaps between rows | `rem` | Space between lines and blocks is part of reading, and vertical space can scroll. |
| Horizontal spacing: inline padding, gutters and gaps along a row | fixed `px` | The width is set by the screen. Growing the padding takes width from the text, which then wraps or is cut off sooner. |
| Borders and dividers | fixed `px` | They are decoration and do not need to grow. |
| Icons and gesture diagrams read alongside text | grow with the text, up to a cap | See [Icons](#icons). |
| How many columns fit | follows the font size | Columns have a minimum width in `rem`, so fewer of them fit as the text grows, rather than each one being squeezed. The [gesture menu](../../src/hooks/useGestureMenuLayout.ts) and the Command Universe grid both work this way. |

Fixed `px` values are the size the `rem` value had at the default font size, so nothing changes for a user at 16px. A design value of 16px horizontal padding is written `16px`, and one of 16px vertical padding is written `1rem`.

The rules come from Josh W. Comeau's ["The Surprising Truth About Pixels and Accessibility"](https://www.joshwcomeau.com/css/surprising-truth-about-pixels-and-accessibility/), which reaches the same split for the same reason: horizontal padding in `rem` shrinks the room left for the text as the text grows. We compared this split against letting all spacing grow with the text, and against growing vertical spacing at a fraction of the text's rate. Growing all spacing crushed the Command Center icons to nothing and pushed the Command Universe header off the screen at large sizes. The fractional rate tightened the gesture menu a little, but not enough to justify a third kind of unit.

## Long text

Text that runs out of room **wraps** onto further lines. The gesture menu labels and the Command Universe section titles do this. Avoid cutting text off with an ellipsis, which hides what the user enlarged it to read.

Some rows cannot wrap, because they are a single line between fixed controls: the dialog title between its buttons, "N thoughts selected" beside the Command Center's Done button, the labels inside the Command Center's pill buttons, and the Command Universe search placeholder. These use [`useFitText`](../../src/hooks/useFitText.ts). It shows the text at its full size while it fits, and above that holds it at the largest size that fits the row, so the text still grows as far as the screen allows. It measures the text once with a canvas rather than by trying sizes in the layout, so a fit costs about 18µs in Chrome on a laptop, and it measures again when the row is resized or the page's web fonts finish loading.

Wrapped text needs more line height than a single line. Where a single-line row has to keep its height, trim the extra leading above the first line and below the last with a negative margin, as [`GestureMenuItem`](../../src/components/GestureMenu/GestureMenuItem.tsx) does (`lineHeight: '1.15em'` with `marginBlock: '-0.075em'`).

## Icons

An icon or gesture diagram that is read alongside text grows with the text. Size it in `rem`. Icon components take their size as a number of pixels, because they write it into the SVG's `width` and `height` attributes, so convert it with [`useRemAsPx`](../../src/hooks/useRemAsPx.ts):

```tsx
<FavoritesIcon size={useRemAsPx(1.125)} />
```

Cap the size where a larger icon would crowd its row or outgrow its button, with `Math.min(useRemAsPx(1.75), 36)`. Header buttons stop at 44px, which is the smallest comfortable touch target, and their icons stop with them.

Two exceptions size themselves differently. [`ToolbarButton`](../../src/components/ToolbarButton.tsx) sizes its icons from the font size with its own formula. The gesture diagrams in the Command Universe grid start out much larger than the text beside them, so they grow at half its rate and stop at 180px ([`CommandUniverseGridItem`](../../src/components/CommandUniverseGridItem.tsx)).

## Layout computed in JavaScript

Some layouts are worked out in JavaScript before they are drawn. The gesture menu predicts how many commands fit from its own constants, rather than measuring the page ([`useGestureMenuLayout`](../../src/hooks/useGestureMenuLayout.ts)). That prediction is only right while it uses the same units as the styles it predicts: a row gap drawn in `rem` has to be budgeted in `rem`, and a gutter drawn in `px` has to be budgeted in `px`. Name each constant after its unit (`ROW_GAP_REM`, `COLUMN_GAP_PX`) so that a mismatch is visible where it is used.

## Checking a change

Look at the change at the default font size and at the largest sizes, from 30 to 40. At 16px it should look exactly as it did before, since every rule above leaves the default unchanged. At the large sizes, check that no text is cut off, that nothing overlaps, and that icons are still in proportion with their labels. The [`render-thoughts`](../../src/e2e/puppeteer/__tests__/render-thoughts.ts) and [`thought-wrap`](../../src/e2e/puppeteer/__tests__/thought-wrap.ts) snapshot tests cover the thoughts themselves at several font sizes.
