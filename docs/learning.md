# Learning Journey

The learning journey helps early users learn commands gradually through normal use. The full design is tracked in [#5481](https://github.com/cybersemics/em/issues/5481). A pinned command stays in a corner widget with a practice-progress ring; opening the ring reveals its gesture and a link to its Command Universe detail page.

## State

`state.learning` ([`LearningState`](../src/@types/LearningState.ts)) holds two independent facts:

```ts
{
  pinnedCommandId: CommandId | null
  progress: Partial<Record<CommandId, { reps: number; targetReps: number }>>
}
```

- Progress is keyed by stable `CommandId`, never by label, category, or position, so relabeling a command preserves its record.
- Progress exists only for the pinned command. A fresh record is created when a command is pinned, capturing the target from `LEARNING_TARGET_REPS` in [`constants.ts`](../src/constants.ts); unpinning, or pinning a different command, erases it. Changing that constant does not change the existing record.
- Reaching `targetReps` fills the ring and plays its flourish. Nothing is marked learned: there is no completion flag, journey status, or history across commands. That is deliberate for now; this work covers the mechanics of the pinned command only.

[`storageModel`](../src/stores/storageModel.ts) saves the pin and progress under the `learning` key. [`initialState`](../src/util/initialState.ts) reads the saved state through that model, just like font size and jump history; no separate hydration action is needed. The decoder validates the stored structure and discards malformed progress records. The widget ignores a saved command that is no longer in the registry. Pinning, unpinning, and awarding a rep save the new learning state through `storageModel.set`. The pinned selection is intentionally device-specific. Practice progress stays local for now; synchronizing learning progress across the user’s devices is deferred. Here, device-local storage means this browser profile and app origin, not shared storage across installations.

## Actions

- [`pinCommand`](../src/actions/pinCommand.ts) — selects the command and starts a fresh progress record, erasing any other command's record. Pinning the already pinned command keeps its record.
- [`unpinCommand`](../src/actions/unpinCommand.ts) — clears the selection and erases its reps.
- [`commandSucceeded`](../src/actions/commandSucceeded.ts) — receives a command-level success report and awards one rep when the invoked command is pinned and the invocation came from an actual keyboard shortcut or gesture. Reps keep counting past the target, and each rep at or past it plays the ring's flourish.

These actions are registered `undoable: false`, and `learning` is listed in `statePropertiesToOmit` in [`undoRedoEnhancer`](../src/redux-enhancers/undoRedoEnhancer.ts), so pinning and practice never add an undo step or get reverted by undoing an edit.

The command runner reports success once per top-level invocation, including a multicursor invocation. It does so when `exec` returns normally or its returned promise resolves, provided the command was executable, did not set a new app error, and did not return `false` for cancellation. A thrown or rejected error prevents a success report. AI commands return their request promises through the first-use disclosure; canceling the disclosure earns nothing. This tests the command's execution boundary; work that a command starts without returning its promise cannot be judged after it finishes. Toolbar, Command Center, Command Universe, and internal calls do not earn practice credit.

## Pinning from the Command Universe

Every command's detail page ([`CommandUniverseDetailPage`](../src/components/CommandUniverse/CommandUniverseDetailPage.tsx)) has a Pin Command row after the command description and gesture, separated by a divider. It reads Unpin Command when that command is the pinned one, and its description names the command that pinning would replace. Pressing it never executes the command.

## The corner widget

[`PinnedCommand`](../src/components/Learning/PinnedCommand.tsx) is mounted in `AppComponent` beside the NavBar and renders nothing while no command is pinned. Its zero-height sticky anchor uses the NavBar's bottom safe-area offset, so the ring stays at the screen corner while scrolling and moves up with the NavBar when the footer enters. The ring is positioned inside that anchor on the `pinnedCommand` z-index layer just above `navbar`. The viewport tooltip is portaled to the document body to keep it outside the sticky anchor's stacking context. The ring has two slots. Docked, it renders inside that sticky anchor. While the overlay is open or fading out, it renders instead in a fixed slot portaled to the document body with the anchor's geometry, on the `pinnedCommandExpanded` layer above the `notification` surface but below popups and dialogs, so it stays docked in the overlay however the page scrolls. The two slots share a Motion `layoutId`, so when the ring changes slot it animates over `medium` from wherever the sticky anchor currently is to the fixed position, and back on close; when the page is not overscrolled the two coincide and nothing moves. Position lives on that outer element, and scale and lift on the button inside it, so the layout animation and the enlargement never share a transform. Keyboard focus follows the ring across the remount. As it scales, the ring is also moved so its center meets the center of the tooltip's row of genie and text, with the move computed from whatever scale is set. That row has a fixed height, so its center is a pure CSS expression of the surface's bottom padding, the tooltip's no-inset padding, half the row height, and the row's offset; the ring's center is the slot offset plus its scaled center height. Both sides include the safe-area inset, and no measurement is involved. The ring's scale and lift follow the surface's eased visibility, so they open and close together with it. The ring stays raised through the exit fade, including when Escape closes the overlay. While raised, it passes pointer events through to the overlay so its Clear control remains usable. When closed, only the ring button accepts pointer events, leaving the surrounding corner open to gestures and taps. The button's hit area is its 73px box extended 16px upward and 12px leftward through a pseudo-element, since the ring fills only the middle 44px of the box and the box already reaches the right edge and the floor; the pseudo-element leaves the box itself, and so the ring's placement and scale origin, unchanged. Tapping the ring opens the tooltip; holding it for `TIMEOUT_LONG_PRESS_THOUGHT` plays a light haptic and opens the command's Command Universe detail page instead, the same as the tooltip's command-name link, and the platform's long-press menu is suppressed. Neither the ring nor the tooltip is text-selectable. Each awarded rep also plays the command's icon animation inside the ring, the same Lottie animation the toolbar plays on activation, and like the toolbar it skips a toggle command that has just been switched off. The button is named `Show gesture for <label>`, describes the current rep count and captured target, and reports whether its tooltip is expanded.

While a command is pinned, the NavBar's inner row leaves `PINNED_COMMAND_RESERVED_WIDTH` free on the right so breadcrumbs and buttons do not run under the ring or its extended tap target. The NavBar's full-width blackout is untouched, so no gap opens behind the bottom chrome. The ring scrolls away before the footer links reach its corner.

## The ring

[`PinnedCommandRing`](../src/components/Learning/PinnedCommandRing.tsx) draws a 73×73 box using values derived directly from the original design in Figma:

- **Track**: a stroked SVG circle with the original design's linear gradient, layer blur, drop shadow, 52% opacity, and `mix-blend-mode: hard-light`.
- **Fill**: in Figma the arc is an annular sector with an along-arc gradient and an *angular progressive layer blur* (tail 14 → head 4, Figma units; a Figma blur value is 2σ). No browser has an angular blur, so the arc is one `conic-gradient` (color and progress angle together) masked to the annulus, stacked five times; each copy is masked to an angular band that crossfades into its neighbours and is wrapped in a div with a different `filter: blur()`. The blur sits on the wrapper so it applies after the inner masks and softens the ring edges. Each rep animates the progress angle over `durations.medium`, starting from the currently visible angle if another rep arrives mid-animation. Mounting a ring, switching pinned commands, and reduced-motion preference render the current angle immediately.
- **Color and flourish**: the fill is mono at rest, including when full. Opening the tooltip reveals the colorful fill in step with the same eased visibility that drives the glow and ring scale; closing it returns the fill to mono. Each rep the current pin earns at or past its target plays a flourish driven by one eased timeline over `durations.pinnedCommandFlourish`: the whole arc spins once, its color rises to the colorful stops at the half turn and falls back to mono by the end, and any fill still short of full closes during the first half of the turn, so the completing rep flows straight into the celebration instead of finishing its own fill first. The colorful layers are mounted while the tooltip is visible or a flourish is playing, and either one can keep them visible when the other fades. `PinnedCommand` counts those reps per pin and passes the count as the ring's `flourish` prop; the ring plays on each change and never on mount, so progress loaded from storage or shown after repinning does not celebrate. Reduced-motion preference keeps the color pulse and skips the spin.

The component is organized into same-file visual layers: `RingTrack` owns the stationary SVG and its unique filter IDs; `RingProgress` coordinates fill, color, and flourish; `BlurredProgressArc` builds the gradient and delegates each mask/blur pair to `RingBlurBand`; `RingIcon` centers the command icon. These component boundaries add no DOM wrappers. `RingProgress` remains mounted at zero progress so its animation state survives changes to the visible fill.

[`TestPinnedCommandRing`](../src/components/modals/TestPinnedCommandRing.tsx) renders the ring at 0%, 30%, the export's 63.5%, 90%, 100% mono, and 100% colorful for the [`pinned-command-ring`](../src/e2e/puppeteer/__tests__/pinned-command-ring.ts) snapshot. The colorful state supplies a fixed color opacity of 1, independently of tooltip interactions or a running flourish. This test uses `screenshot({ preserveFilters: true })`, so the snapshot covers geometry, gradients, blur, and shadows.

## Gesture tooltip

[`PinnedCommandTooltip`](../src/components/Learning/PinnedCommandTooltip.tsx) uses the shared [`NotificationSurface`](../src/components/Notifications/NotificationSurface.tsx), so it sits where [`Tip`](../src/components/Notifications/Tip.tsx) does, blurs the content beneath it the same way, and fades the same way; unlike Tip it does not swipe to dismiss, since a swipe over it is a gesture trace. At the bottom-right anchor that blur and its scrim are a corner rather than a full-width band: a box sized to the content and feathered by one shared elliptical mask, so on a landscape phone the rest of the thoughtspace stays sharp. Its visibility animation uses the Sidebar's gentle open curve and the Command Center's gentle-start close curve. The ring's scale and color follow that same eased opacity. It differs from Tip in three ways:

- **Glow.** The surface's `pinnedCommand` glow variant paints `public/img/pinned-command/pinned-command-glow.avif` with extents that do not follow the content height, unlike Tip's. Portrait and landscape are keyed by the `lg` breakpoint in [`notification.ts`](../src/recipes/notification.ts), which is where the tooltip's anchor switches. The glow element is the image's own footprint: the image's constants live in its aspect ratio, and every other value is a fraction of one viewport dimension. Portrait scales with viewport width and anchors left, matched to the design at 412×922; landscape scales with viewport height and anchors right, matched at 922×412, with a heavier blur. Sizing from a single dimension avoids iOS Safari's unstable `vh` in portrait, and the bottom anchor adds the safe-area inset so the bright band follows the text above the home indicator. Tablet and desktop share the landscape branch, where the glow must stay localized in the corner at the phone size, so each height-relative value there is capped at its value on a 412px-tall viewport. The surface owns the image paths, applies the selected path directly as a background image, and prefetches it. Static rainbow-glow placement is defined directly in the anchor styles. Motion supplies the ring’s animated transform directly through `useMotionTemplate`, with `useBreakpoint` selecting the responsive bottom padding; no feature-specific animation variables are needed. Notification easing and the shared corner blur/scrim mask are defined in `constants.ts`.
- **Content.** A row of the learning genie button, the command's name as a button with a chevron that opens its Command Universe detail page directly, and one line saying how to activate it: trace the gesture on touch devices, press the shortcut otherwise, or open the Command Universe when the command has neither. Text is left-aligned at both anchors. The genie and the text form one vertically centered row so they read as a unit with the ring in the corner; Clear hangs below that row, outside its flow and in the surface's bottom padding, so it does not pull the row's center down. That padding is tight on devices without a safe-area inset, so the tooltip adds bottom padding that shrinks as the inset grows.

- **Diagram.** Below `lg`, when the command has a gesture, its canonical gesture from the command registry is drawn large above the text with the Command Universe detail page's diagram styling. Behind it is its own glow, `public/img/pinned-command/pinned-command-gesture-glow.avif`, positioned and sized relative to the diagram box so the two stay aligned on every device; it is separate from the surface glow because the diagram can be absent. There is no landscape design for the diagram yet.

The tooltip is built to be practiced on. It passes `passThrough` to the surface, which makes the content layer ignore pointer events so a trace that starts over the diagram reaches the thoughtspace and can activate the command; only the text row opts back in. Touch input is then split by what the finger does and where it starts: a tap anywhere, on the tooltip or off it, dismisses; a drag that starts in the gesture zone is a gesture trace and leaves the tooltip open; a drag that starts outside it, in the scroll zone or on the toolbar, is a scroll and dismisses. The tooltip tells these apart itself, from document-level pointer events in the capture phase. A tap is a pointer that never strays past `TAP_SLOP` from where it went down, judged on every move since a trace can end where it began; a pointer the browser cancels is not a tap. The zone comes from the same [`isInGestureZone`](../src/util/isInGestureZone.ts) and left-handed setting that `MultiGesture` uses, so the scroll zone is defined once. Pointers that go down on the dev-only tuning panel, marked `data-pinned-command-debug`, are ignored so the panel can be operated while the tooltip stays open. While a gesture is in progress, read from the gesture store's current sequence, the surface's blur, scrim, and glow and the tooltip's text row fade to half opacity through the surface's `dimmed` prop, and the diagram stays fully visible so it can be traced over. The gesture menu does not open while the tooltip is open: `handleGestureSegment` checks `tooltipOpen` in [`pinnedCommand`](../src/stores/pinnedCommand.ts), a ministore that `PinnedCommand` keeps in step with its open state. A rep earned while the tooltip is open closes it, after counting. Clear, a tap, and Escape also dismiss the tooltip. The command-name link opens its Command Universe detail page immediately, without the page-entry zoom, while keeping the grid available through Back. Opening and dismissing the tooltip does not execute the command, change the pin, or award practice reps.

The ring records the editor's selection offsets before pointer activation can move focus. When the command-name button opens the Command Universe, its open action preserves that snapshot rather than replacing it with the selection inside the tooltip. This lets commands that act on selected text continue to use the editor range.

[`TestPinnedCommandTooltip`](../src/components/modals/TestPinnedCommandTooltip.tsx) renders the open tooltip for Context View so the [`pinned-command-tooltip`](../src/e2e/puppeteer/__tests__/pinned-command-tooltip.ts) snapshots can guard its layout at a portrait and a landscape viewport. The screenshot helper disables CSS filters, so the snapshots cover placement and extents, not the blur.
